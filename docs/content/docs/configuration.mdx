安装并完成首次启动后，配置与订阅是日常维护的核心。ClashBar 将工作文件放在 `~/Library/Application Support/clashbar`；配置相关文件位于 `…/clashbar/config`，并在菜单栏面板的配置菜单中提供切换入口。

面板内选节点、测延迟见 [日常使用](/docs/daily-use)；按 Wi‑Fi 自动换配置见 [SSID 策略](/docs/ssid-strategy)。

## 数据目录

| 路径 | 作用 | 管理建议 |
| --- | --- | --- |
| `config/` | 用户配置（`.yaml` / `.yml`）与订阅导入结果 | 建议备份；可手动维护文件名 |
| `core/` | 运行时 `mihomo` 二进制 | 升级/替换前先停止内核 |
| `icon/` | 代理组图标磁盘缓存（节点页展示用） | 由程序维护；可安全删除，会按需重新下载 |
| `ui/` | Mihomo External UI 静态资源（配置了 `external-ui` / `external-ui-url` 时由内核生成） | 由内核维护；清理后重启内核可重新拉取 |
| `logs/` | 运行日志与排障输出 | 排障后可按需清理 |
| `state/` | 应用运行状态与会话数据 | 建议由程序维护，勿手改 |

根目录下还可能出现缓存文件（如 `cache.db`）以及内核生成的 GEO / 规则相关文件。切换内核后若异常，可参考 [快速开始 · 切换内核](/docs/quick-start#切换内核) 清理缓存。

<Callout type="info" title="维护建议">
日常只需维护 `config/`；`icon/`、`ui/`、`logs/`、`state/`、`core/` 等优先交给 ClashBar 或内核管理，以降低运行状态不一致风险。
</Callout>

## 配置发现规则

应用扫描 `config/` 时遵循：

- **仅识别** `.yaml` / `.yml` 文件
- 按**文件名排序**加载
- **未手动指定**当前配置时，默认选中列表中的**第一个**配置

外部增删改文件后，可使用「重载配置文件」重新扫描列表；运行中内核需「重新加载配置」或重启内核后才会完整应用变更。

## 导入本地配置

在配置菜单中选择「导入本地配置」，选择有效的 Mihomo YAML。导入后从「切换配置」选中它；启动前会做配置校验。

若校验失败，请查看「日志」中 Mihomo 返回的错误，修正 YAML 后重新加载。缺少 GEO / MMDB 时的处理见 [常见问题 · MMDB](/docs/troubleshooting#日志提示找不到-mmdb-并开始下载)。

## 导入订阅链接

选择「导入订阅链接」，填写：

- **订阅链接**：可访问的 HTTP 或 HTTPS 配置地址
- **文件名**：可选；留空时根据链接推断 YAML 文件名
- **自动更新间隔**（可选）：按小时后台重新拉取

订阅下载完成后会出现在「切换配置」中。可复制原始订阅链接或删除该配置（删除会同时移除订阅元数据）。

## 切换与刷新

- 在「切换配置」中选择当前配置
- 对订阅配置可**立即刷新**单个来源
- 「更新订阅链接」可**批量**更新已保存订阅
- 「重新加载配置」让运行中内核重读当前配置
- 「重载配置文件」重新扫描配置目录列表
- 「在访达中显示」打开配置目录；设置中可打开[内核目录](/docs/settings)

远程更新成功但节点/规则未变时，见 [常见问题 · 远程配置更新后未生效](/docs/troubleshooting#远程配置更新后未生效)。

## 按 Wi‑Fi 切换配置

可开启 Wi‑Fi 自动切换，并将当前 SSID 绑定到某份配置。说明见 [SSID 策略](/docs/ssid-strategy)。

## 配置中的运行时设置

「设置」标签可覆盖端口、允许局域网、IPv6、TCP 并发、日志级别等。详见 [设置与维护](/docs/settings)。

复杂的代理组、规则提供者与 DNS 仍应在 YAML 中维护权威配置。全部能力对照见 [功能总览](/docs/features)。
